# AIRA β v2.1.0 リリースノート — 400 シナリオ品質評価で鍛えた Structured RAG と 50 件のバグフィックス

## はじめに

AI Research Administrator（AIRA）β v2.1.0 をリリースしました。

本バージョンの目玉は **Structured RAG**（構造化検索拡張生成）の導入と、**400 の品質評価シナリオ**を用いた徹底的なバグハントです。20 ラウンド × 20 プロンプトの品質評価を繰り返し、セキュリティ・安定性・堅牢性に関わる **50 件のバグ**を検出・修正しました。

- **GitHub**: https://github.com/nahisaho/aira
- **Docker**: `ghcr.io/nahisaho/aira:latest`

## 新機能

### 🧠 Structured RAG — プロジェクト単位の知識抽出・検索

Microsoft の [TypeAgent](https://github.com/microsoft/typeagent) の構造化メモリアーキテクチャを参考に、プロジェクト単位の RAG 機能を実装しました。

```
ユーザーの会話/ファイル
    ↓ LLM による抽出
[エンティティ | アクション | トピック]
    ↓ トークンベース転置インデックス
SQLite 内蔵インデックス
    ↓ 検索 → rag-context.md 生成
Copilot CLI のコンテキストに自動注入
```

**主な特徴：**

| 機能 | 説明 |
|------|------|
| エンティティ抽出 | 会話・ファイルから人名、技術用語、概念を LLM で抽出 |
| アクション抽出 | 「〜を実装した」「〜を修正した」等の行動を構造化記録 |
| トピック抽出 | 会話のテーマ・分野を自動分類 |
| 転置インデックス | トークンベースの高速全文検索（外部エンジン不要） |
| コンテキスト注入 | `rag-context.md` として CLI セッションに自動挿入 |
| プロジェクト設定 | RAG の有効/無効、最大コンテキスト文字数をプロジェクト毎に設定可能 |
| 手動再インデックス | API 経由でインデックスの再構築が可能 |

### 🧪 品質評価フレームワーク — 400 シナリオによる網羅的検証

品質評価の手法として、20 ラウンド × 20 プロンプト = 合計 **400 シナリオ**の評価パイプラインを構築しました。

```
Round 1  → QE-001〜020: 6 件修正
Round 2  → QE-021〜040: 4 件修正
Round 3  → QE-041〜060: 3 件修正
Round 4  → QE-061〜080: 4 件修正
Round 5-8  → QE-081〜160: 4 件修正
Round 9-12 → QE-161〜240: 6 件修正
Round 13 → QE-241〜260: 3 件修正
Round 14 → QE-261〜280: 3 件修正
Round 15 → QE-281〜300: 4 件修正
Round 16 → QE-301〜320: 5 件修正
Round 17 → QE-321〜340: 5 件修正
Round 18-20 → QE-341〜400: 0 件 ← 品質安定化を確認
```

ラウンドを重ねるごとに検出数が減少し、最終 3 ラウンドで **修正ゼロ**を達成。品質の収束を定量的に確認しました。

### 🎭 Playwright E2E テスト

Playwright を使用したエンドツーエンドテストを導入し、WebSocket → CLI パイプライン全体の品質を検証しています。

- **基本品質テスト**: 39 テストケース（UI 操作、プロジェクト管理、設定画面）
- **Co-Scientist スキルテスト**: WS パイプライン経由のスキル割り当て＆実行
- **科学的探査テスト**: SATORI パイプラインをモデルにした 5 つの高度なプロンプト
  - SCI-01: 仮説駆動統計検定（PICO / Mann-Whitney U）
  - SCI-02: モンテカルロ収束解析（π 推定 / O(1/√N) 検証）
  - SCI-03: バリアント分類＆薬理ゲノミクス（ACMG/AMP / CYP 代謝）
  - SCI-04: 気候データ時系列解析（トレンド分解 / ACF / 予測）
  - SCI-05: 実験計画法（2³ 要因配置 / ANOVA / 応答曲面）

## バグフィックス

### 🔴 セキュリティ修正（14 件 HIGH）

本バージョンで最も重要な改善領域です。品質評価プロンプトにより、プロダクションで悪用される可能性のある脆弱性を検出・修正しました。

| # | カテゴリ | 修正内容 | 対象ファイル |
|---|---------|---------|-------------|
| 1 | パス走査 | 静的ファイル配信のディレクトリトラバーサル防止 | `file.service.ts` |
| 2 | プロトタイプ汚染 | MCP 設定の `__proto__` / `constructor` キー拒否 | `mcp.service.ts` |
| 3 | プロトタイプ汚染 | ネストされたオブジェクトの再帰的汚染防止 | `mcp.service.ts` |
| 4-7 | JSON パース | `JSON.parse` の安全なエラーハンドリング（4 箇所） | 複数ファイル |
| 8 | ヘッダー注入 | Content-Disposition ヘッダーインジェクション防止 | `files.ts` |
| 9 | ストリーム | CLI parseLine のクラッシュ防止（不正 JSON 入力） | `container-runner.ts` |
| 10 | メモリ | hashFile のストリーミング化（大容量ファイル対応） | `file.service.ts` |
| 11 | 競合状態 | startRun のレース条件修正（プレースホルダー予約方式） | `container-runner.ts` |
| 12 | バリデーション | プロジェクト ID の UUID フォーマット検証ミドルウェア | `security.ts` |
| 13 | XSS | SVG ファイルの Content-Type 強制（`image/svg+xml`） | `files.ts` |
| 14 | 情報漏洩 | シークレットパターン検出による機密情報ブロック | `file.service.ts` |

### 🟡 安定性修正（28 件 MEDIUM）

長時間�kind やエッジケースで発生する安定性問題を系統的に修正しました。

| カテゴリ | 修正内容 |
|---------|---------|

| ストリーム | エラーハンドラー追加（未処理例外防止） |

## 技術的変更

### DB エンジン移行: better-sqlite3 → sql.js

ネイティブバインディングの `better-sqlite3` から WASM ベースの `sql.js` に移行しました。

**移行理由：**
- Docker イメージのマルチプラットフォーム対応の簡素化
- ネイティブビルド依存（Python, make, gcc）の排除
- GitHub Actions CI の安定化

**影響：**
- パフォーマンスは実用上問題なし（AIRA のワークロードでは差異なし）
- 全テストファイルの依存を sql.js ベースに統一

### preset_id マイグレーション修正

Co-Scientist スキルの E2E テスト中に発見された DB マイグレーション問題を修正。`preset_id` カラムの追加が既存テーブルで正しく実行されるようになりました。
