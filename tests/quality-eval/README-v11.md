# 品質評価プロンプト v11 (QE-201 〜 QE-220)

Round 11: エッジケース・RAG詳細・データフロー

| ID | 評価軸 | プロンプト | 期待される動作 |
|----|--------|-----------|---------------|
| QE-201 | G(RAGコンテキスト) | RAGで抽出されたエンティティに同音異義語がある場合 | コンテキストで区別されるか適切にスコアリング |
| QE-202 | L(入力バリデーション) | JSONフィールドにprototype汚染ペイロード(__proto__) | プロトタイプ汚染が防止される |
| QE-203 | K(並行安全性) | WebSocketメッセージの順序保証 | メッセージが送信順序通りに処理される |
| QE-204 | M(API整合性) | APIレスポンスのContent-Typeヘッダー一貫性 | すべてのJSONレスポンスがapplication/json |
| QE-205 | A(応答品質) | プログラミング初心者向けの説明を依頼 | 専門用語を避けた分かりやすい説明 |
| QE-206 | B(スキル連携) | スキル間の依存関係がある場合 | 依存解決または適切なエラーメッセージ |
| QE-207 | C(ファイル生成) | UTF-8 BOM付きファイルの処理 | BOMが正しく処理される |
| QE-208 | D(MCP活用) | MCP設定で環境変数の参照($HOME) | 環境変数が正しく展開される |
| QE-209 | E(デバッグ) | 再現不能な間欠的エラーの診断 | ログ収集とデバッグ手順のガイド |
| QE-210 | H(セッション継続性) | セッションデータが100MBを超えた場合 | 古いデータのアーカイブまたは警告 |
| QE-211 | I(ファイル更新) | ファイルのタイムスタンプが未来の日時 | 正常に処理される |
| QE-212 | J(ディレクトリ構造) | ワークスペース内の循環シンボリックリンク | 無限ループ防止 |
| QE-213 | N(エージェント管理) | エージェントのバージョンロールバック | 特定コミットにチェックアウト可能 |
| QE-214 | G(RAGコンテキスト) | RAGインデックスのバックアップとリストア | エクスポート/インポート機能 |
| QE-215 | K(並行安全性) | トランザクション分離レベルの確認 | SQLiteのSERIALIZABLE分離が維持 |
| QE-216 | L(入力バリデーション) | RegExp DoS (ReDoS) パターンの入力 | 正規表現のタイムアウトまたは事前検証 |
| QE-217 | M(API整合性) | 204 No Content レスポンスのボディ | ボディが空であること |
| QE-218 | A(応答品質) | 「テストカバレッジを80%に上げる戦略を教えて」 | 段階的な戦略と具体的なテスト種類を提案 |
| QE-219 | C(ファイル生成) | .gitignoreパターンに一致するファイル生成 | 生成されるがGit追跡からは除外 |
| QE-220 | E(デバッグ) | ネットワークタイムアウトの原因特定依頼 | DNS、ファイアウォール、接続先の診断手順 |
