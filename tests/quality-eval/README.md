# AIRA 品質評価プロンプト集（v2.1.0）

SATORI × ToolUniverse 品質評価記事の手法を参考に、AIRA のプラットフォーム機能を
MECE（Mutually Exclusive, Collectively Exhaustive）の原則で網羅的に評価する
**20 本の品質評価プロンプト**を設計しました。

## 評価軸

| # | 評価軸 | 説明 |
|---|--------|------|
| A | **プロンプト→応答品質** | ユーザーの指示に対する応答の正確性・完全性 |
| B | **スキル連携** | Agent Skills の自動発見・連鎖参照・適切な適用 |
| C | **ファイル生成・検出** | コード/論文/図表の生成とファイル検出の完全性 |
| D | **MCP ツール活用** | 外部データベース API の適切な選択・呼び出し・統合 |
| E | **デバッグ・自己修復** | エラー検知→原因特定→修正→再実行の自律サイクル |
| F | **End-to-End 自動化** | プロンプト投入から最終成果物まで人手介入ゼロでの完遂 |
| G | **RAG コンテキスト** | Structured RAG による知識蓄積・検索・コンテキスト注入 |
| H | **セッション継続性** | 複数ターンにわたる会話の文脈保持・セッション再開 |

## 判定基準

各プロンプトの結果を以下の 3 段階で判定:

| 判定 | 基準 |
|------|------|
| ✅ Pass | 期待成果をすべて満たす |
| ⚠️ Partial | 一部の期待成果が欠落、または品質が不十分 |
| ❌ Fail | 主要な期待成果を満たさない、またはエラーで中断 |

### 修正内容

1. **`container-runner.ts`**: `getSessionName()` で projectId 全体を使用（衝突防止）
2. **`container-runner.ts`**: `parseLine()` で JSON パース失敗時にログ出力
3. **`container-runner.ts`**: 非ゼロ終了+部分出力時に stderr をログ出力
4. **`ws.service.ts`**: 空白のみプロンプトの早期拒否
5. **`rag-extractor.ts`**: LLM 抽出失敗時に同期トークンでフォールバック
6. **`rag.service.ts`**: `indexStructuredKnowledge()` 内で per-item エラーハンドリング
