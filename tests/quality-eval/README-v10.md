# 品質評価プロンプト v10 (QE-181 〜 QE-200)

Round 10: パフォーマンス・スケーラビリティ・リソース管理

| ID | 評価軸 | プロンプト | 期待される動作 |
|----|--------|-----------|---------------|
| QE-181 | K(並行安全性) | 50プロジェクトを同時にアクティブ化 | メモリ使用量が線形増加し、OOMにならない |
| QE-182 | M(API整合性) | 大量メッセージ(1万件)のページネーション | レスポンスタイムが一定に保たれる |
| QE-183 | L(入力バリデーション) | リクエストレートリミットの確認 | 過剰リクエストに429レスポンス |
| QE-184 | A(応答品質) | 「このファイルのパフォーマンスを最適化して」 | 具体的なボトルネック特定と改善案 |
| QE-185 | G(RAGコンテキスト) | RAGインデックス10万エントリでの検索性能 | 検索が1秒以内に完了 |
| QE-186 | C(ファイル生成) | 10MBのファイルを生成してダウンロード | ストリーミングで効率的に転送 |
| QE-187 | D(MCP活用) | MCPサーバーが10台同時に動作 | 各サーバーのリソース使用が制限される |
| QE-188 | E(デバッグ) | CPU使用率100%の状態でのタスク実行 | リソース競合のハンドリングまたは待機 |
| QE-189 | H(セッション継続性) | 100セッションの同時管理 | セッションリストの取得が即座に完了 |
| QE-190 | I(ファイル更新) | 100個のファイルが同時に変更された場合のインデックス更新 | バッチ処理で効率的にインデックス更新 |
| QE-191 | N(エージェント管理) | 20個のエージェントリポジトリを登録 | 各リポジトリが独立して管理される |
| QE-192 | B(スキル連携) | スキルファイルの変更検出と自動リロード | ファイルシステム監視で変更を検出 |
| QE-193 | J(ディレクトリ構造) | 10万ファイルを含むワークスペースのファイルツリー構築 | ツリー構築がタイムアウトしない |
| QE-194 | K(並行安全性) | DBバックアップ中のクエリ実行 | 読み取りはブロックされない |
| QE-195 | L(入力バリデーション) | multipart/form-data でのファイルアップロード | ファイルタイプ・サイズバリデーション |
| QE-196 | M(API整合性) | APIバージョニングの互換性 | 古いクライアントとの後方互換性 |
| QE-197 | A(応答品質) | 「10個のマイクロサービスの設計をして」 | 段階的に設計を提示、一度に全部出さない |
| QE-198 | C(ファイル生成) | 同一ファイルの複数バージョン管理 | 最新バージョンが保持される |
| QE-199 | E(デバッグ) | ディスク容量不足時のエラーハンドリング | 適切なエラーメッセージと空きスペース確認 |
| QE-200 | G(RAGコンテキスト) | 複数プロジェクトのRAGデータ合計サイズ管理 | グローバルなストレージ使用量の監視 |
