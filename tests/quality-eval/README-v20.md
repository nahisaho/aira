# 品質評価プロンプト Round 20 (QE-381〜QE-400)

前回ラウンドで3件検出。収束確認ラウンド。

## 評価プロンプト

### QE-381 [K: 並行安全性 / N: エージェント管理]
**プロンプト**: 「stopRun()が呼ばれてからonDoneコールバックが実行されるまでの間に、activeRunsの状態は一貫していますか？」
**期待**: placeholder reserveにより一貫性が保たれること

### QE-382 [L: セキュリティ / M: API整合性]
**プロンプト**: 「UUID検証ミドルウェアが追加されたが、スキルIDやMCP設定IDにも同様の検証はありますか？」
**期待**: DB内のUUID参照は安全（SQLパラメータ化済み）、ファイルパスに使う箇所のみ要検証

### QE-383 [G: RAGコンテキスト / L: セキュリティ]
**プロンプト**: 「RAG searchKnowledgeのクエリ文字列にSQLインジェクションは可能ですか？」
**期待**: パラメータ化クエリで安全

### QE-384 [C: ファイル生成・検出 / L: セキュリティ]
**プロンプト**: 「resolveFilePathで相対パスが使われている場合、正規化後にワークスペース外を指す可能性はありますか？」
**期待**: path.resolve + startsWith チェックで安全

### QE-385 [D: MCP活用 / K: 並行安全性]
**プロンプト**: 「MCP設定の一時ファイル書き込みとscavengeStaleConfigsの削除が同時に実行された場合、競合は発生しますか？」
**期待**: ファイル名がUUIDベースで衝突しない、unlinkの失敗はtry-catchで処理

### QE-386 [E: デバッグ / A: 応答品質]
**プロンプト**: 「CLIプロセスが異常終了コード（例: 137 = OOM kill）を返した場合、ユーザーにはどのようなエラーメッセージが表示されますか？」
**期待**: exit codeを含むエラーメッセージが返されること

### QE-387 [H: セッション継続性 / G: RAGコンテキスト]
**プロンプト**: 「既存のRAGインデックスがあるプロジェクトで、新しいメッセージを送信した場合、インデックスは正しく更新されますか？」
**期待**: indexMessageTokensが新しいメッセージのトークンを追加すること

### QE-388 [I: ファイル更新 / J: ディレクトリ構造]
**プロンプト**: 「reconcileProjectFilesでワークスペースが空（ファイル0件）の場合、DB内のファイルレコードはクリアされますか？」
**期待**: スキャン結果が空の場合も正しく処理されること

### QE-389 [N: エージェント管理 / M: API整合性]
**プロンプト**: 「agentRunsテーブルのstatus遷移（queued→running→completed/failed/timeout）に不正な遷移パスはありますか？」
**期待**: ステータス遷移が一方向で制御されていること

### QE-390 [B: スキル連携 / L: セキュリティ]
**プロンプト**: 「スキルのcopilot-instructions.mdファイルに悪意のある指示が含まれている場合、何らかの検証やサニタイズは行われますか？」
**期待**: スキルファイルはユーザーが管理するものなので信頼する（意図的設計）

### QE-391 [F: E2E自動化 / K: 並行安全性]
**プロンプト**: 「flushToDiskの100msデバウンスが動作中にアプリがクラッシュした場合、最新のDB変更は失われますか？」
**期待**: 最大100msのデータ損失は許容される設計（shutdown時にflush呼び出し確認）

### QE-392 [L: 入力バリデーション / M: API整合性]
**プロンプト**: 「プロジェクト名が空文字列の場合、作成は拒否されますか？」
**期待**: zodバリデーションで空文字列を拒否すること

### QE-393 [G: RAGコンテキスト / A: 応答品質]
**プロンプト**: 「RAGの転置インデックスで同じ単語が100件以上のknowledgeに紐づいている場合、検索性能は劣化しますか？」
**期待**: score順ソート + LIMIT で制御されていること

### QE-394 [C: ファイル生成・検出 / E: デバッグ]
**プロンプト**: 「onFileCreatedコールバックで、ファイルパスが空文字列の場合はどうなりますか？」
**期待**: 空文字列チェックまたはpath.resolve で安全に処理

### QE-395 [D: MCP活用 / N: エージェント管理]
**プロンプト**: 「MCPの一時設定ファイルがtmpディレクトリに残り続けた場合（scavengeが呼ばれない場合）、ディスク使用量は問題になりますか？」
**期待**: scavengeはstartup時に呼ばれ、各ファイルは小さい（数KB）ので問題ない

### QE-396 [H: セッション継続性 / L: セキュリティ]
**プロンプト**: 「CLI --resume で他のプロジェクトのセッション名を指定した場合、セッションは乗っ取られますか？」
**期待**: セッション名はproject-specific（プロジェクト名ベース）で分離されている

### QE-397 [J: ディレクトリ構造 / I: ファイル更新]
**プロンプト**: 「ensureWorkspaceRepoで.gitディレクトリの作成に失敗した場合（パーミッション不足）、以降のCLI実行はどうなりますか？」
**期待**: エラーがキャッチされ、明確なエラーメッセージが返されること

### QE-398 [M: API整合性 / L: セキュリティ]
**プロンプト**: 「POSTリクエストのContent-Typeがapplication/json以外の場合（例: text/plain）、ボディパースはどうなりますか？」
**期待**: Honoフレームワークが不正なContent-Typeを拒否するか、c.req.json()が例外を投げること

### QE-399 [K: 並行安全性 / G: RAGコンテキスト]
**プロンプト**: 「RAGの非同期LLM抽出がキューに溜まり、同時実行数が上限を超えた場合、どうなりますか？」
**期待**: acquireSlot/releaseSlotでセマフォ制御されていること

### QE-400 [A: 応答品質 / N: エージェント管理]
**プロンプト**: 「AIRAの全APIエンドポイントがエラー時にJSON形式のレスポンスを返しますか？（HTMLエラーページが返されることはありませんか？）」
**期待**: app.onError グローバルハンドラーでJSON形式を保証
