# 品質評価プロンプト v14 (QE-261 〜 QE-280)

Round 14: 残存リスク確認・防御コード品質・堅牢性

| ID | 評価軸 | プロンプト | 期待される動作 |
|----|--------|-----------|---------------|
| QE-261 | L(入力バリデーション) | MCP作成時のconfig内にネストされた__proto__キー | 再帰的にプロトタイプ汚染キーが除去される |
| QE-262 | K(並行安全性) | DBトランザクション中にUNIQUE制約違反が発生 | ROLLBACKで整合性が保たれる |
| QE-263 | M(API整合性) | PUT/PATCH/DELETEエンドポイントにContent-Length:0で送信 | ボディなしリクエストが適切に処理される |
| QE-264 | A(応答品質) | セッション名に制御文字(\n\r\t)を含む場合 | サニタイズされるか拒否される |
| QE-265 | E(デバッグ) | container-runnerのstderrバッファが巨大(10MB)になった場合 | メモリ使用が制限される |
| QE-266 | G(RAGコンテキスト) | RAG検索クエリに正規表現メタ文字を含む場合 | SQL LIKE/GLOBのエスケープまたはプリペアドステートメントで安全 |
| QE-267 | C(ファイル生成) | ファイルアップロード時のContent-Typeバリデーション | 危険なContent-Type(text/html等)の制限 |
| QE-268 | D(MCP活用) | MCPサーバー起動コマンドにシェルインジェクション | コマンドが安全にエスケープされる |
| QE-269 | H(セッション継続性) | --name引数にシェル特殊文字を含むセッション名 | エスケープされてCLIに安全に渡される |
| QE-270 | I(ファイル更新) | reconcile中に別プロセスがファイルを削除した場合 | ENOENT/ENOTDIRエラーが適切にハンドリング |
| QE-271 | N(エージェント管理) | エージェントプロセスのstdout/stderrパイプが壊れた場合 | EPIPE/ERR_STREAM_DESTROYEDが適切に処理 |
| QE-272 | K(並行安全性) | closeDatabase()後にgetDatabase()が呼ばれた場合 | 明確なエラーメッセージがスロー |
| QE-273 | L(入力バリデーション) | スキル登録時のsource_urlに javascript: プロトコル | 安全でないプロトコルが拒否される |
| QE-274 | M(API整合性) | 大文字のHTTPメソッド(GET/POST)以外(gEt/pOsT)の処理 | 大文字小文字を区別せず処理 |
| QE-275 | A(応答品質) | Unicode正規化(NFC/NFD)の違いによる検索不一致 | 正規化されて一貫した検索結果 |
| QE-276 | E(デバッグ) | CLI実行中にディスクフルが発生した場合のDB書き込み | ENOSPCエラーがログされ安全に失敗 |
| QE-277 | G(RAGコンテキスト) | 同一メッセージの再インデックス（冪等性確認） | ON CONFLICT DO NOTHINGで重複なし |
| QE-278 | C(ファイル生成) | ファイルサイズが0のファイルのハッシュ計算 | 空ファイルの有効なハッシュが返される |
| QE-279 | B(スキル連携) | スキルディレクトリが読み取り専用の場合 | 適切なエラーメッセージでスキップ |
| QE-280 | D(MCP活用) | MCP temp configファイルの権限が他ユーザーから読める | 0o600権限で作成される |
