# 品質評価プロンプト v9 (QE-161 〜 QE-180)

Round 9: フロントエンド品質・React・アクセシビリティ

| ID | 評価軸 | プロンプト | 期待される動作 |
|----|--------|-----------|---------------|
| QE-161 | A(応答品質) | フロントエンドのエラーバウンダリでキャッチされない例外が発生 | UI全体がクラッシュせず、エラー表示コンポーネントに切り替わる |
| QE-162 | L(入力バリデーション) | プロジェクト作成フォームでXSSペイロードを入力 | React DOMエスケープで安全にレンダリング |
| QE-163 | K(並行安全性) | WebSocket再接続中にメッセージ送信ボタンを連打 | 二重送信防止、接続確立後に送信 |
| QE-164 | M(API整合性) | APIレスポンスが空オブジェクト{}の場合のUI表示 | 空状態の適切なフォールバック表示 |
| QE-165 | H(セッション継続性) | ブラウザリロード後のUI状態復元 | 選択中のプロジェクトとチャット履歴が復元 |
| QE-166 | I(ファイル更新) | ファイルツリーで1000個以上のファイルを表示 | 仮想スクロールまたはページングで性能維持 |
| QE-167 | C(ファイル生成) | ファイル生成の進捗をリアルタイム表示 | WebSocketイベントでファイル一覧が即座に更新 |
| QE-168 | E(デバッグ) | コンソールエラーが発生した状態でチャット送信 | フロントエンドエラーがバックエンドに影響しない |
| QE-169 | B(スキル連携) | スキル設定UIで無効なJSON入力 | バリデーションエラーが即座にフィードバック |
| QE-170 | D(MCP活用) | MCP設定UIでサーバーURLにlocalhostを指定 | 接続テスト機能で事前検証 |
| QE-171 | G(RAGコンテキスト) | RAG設定UIでmax_context_charsに負の値を入力 | フロントエンドバリデーションで拒否 |
| QE-172 | J(ディレクトリ構造) | ファイルツリーでシンボリックリンクの表示 | リンクか通常ファイルか判別可能 |
| QE-173 | N(エージェント管理) | エージェント一覧のリアルタイム更新 | WebSocketで状態変更が即座に反映 |
| QE-174 | L(入力バリデーション) | チャット入力に10万文字を貼り付け | 文字数制限またはパフォーマンス劣化防止 |
| QE-175 | K(並行安全性) | 複数タブで同一プロジェクトのRAG設定を変更 | 最新の設定が反映される |
| QE-176 | M(API整合性) | ネットワーク切断中のAPI呼び出し | リトライ機構またはオフライン通知 |
| QE-177 | A(応答品質) | 長い応答（1万文字以上）の表示性能 | スムーズなスクロールとレンダリング |
| QE-178 | C(ファイル生成) | 生成ファイルのプレビュー・差分表示 | diff形式で変更箇所が視覚的に確認可能 |
| QE-179 | E(デバッグ) | フロントエンドのメモリ使用量モニタリング | 長時間使用でメモリリークがない |
| QE-180 | H(セッション継続性) | ブラウザの戻るボタンでの状態遷移 | ルーティング状態が正しく管理される |
