# 品質評価プロンプト Round 19 (QE-361〜QE-380)

前回ラウンドで1件検出。最終収束確認ラウンド。

## 評価プロンプト

### QE-361 [L: セキュリティ / K: 並行安全性]
**プロンプト**: 「2つのクライアントが同じプロジェクトの同じセッションに同時にメッセージを送信した場合、レース条件は発生しますか？」
**期待**: activeRuns / run lock が重複実行を防止すること

### QE-362 [L: 入力バリデーション / M: API整合性]
**プロンプト**: 「プロジェクトIDにUnicode文字（例: 日本語）を含む値を渡した場合、ファイルパスは安全に処理されますか？」
**期待**: IDはUUID形式で検証されるか、パス結合が安全であること

### QE-363 [G: RAGコンテキスト / A: 応答品質]
**プロンプト**: 「RAGが有効だが知識レコードが0件の場合、rag-context.mdは生成されますか？空ファイルになりませんか？」
**期待**: 空コンテキストの場合はファイル生成をスキップすること

### QE-364 [D: MCP活用 / L: セキュリティ]
**プロンプト**: 「MCP設定のenvに極端に長い値（100KB）を設定した場合、メモリ問題は発生しますか？」
**期待**: 環境変数値のサイズ制限があること

### QE-365 [N: エージェント管理 / K: 並行安全性]
**プロンプト**: 「実行中のrunをstopした直後にstartRunを呼んだ場合、前回のクリーンアップと新規開始が競合しませんか？」
**期待**: stop完了を待ってからstartを許可するか、lockで保護すること

### QE-366 [C: ファイル生成・検出 / I: ファイル更新]
**プロンプト**: 「ワークスペース内でシンボリックリンクのループ（a→b→a）が存在する場合、ファイルスキャンは無限ループになりませんか？」
**期待**: depth制限やvisitedセットで防止すること

### QE-367 [E: デバッグ / A: 応答品質]
**プロンプト**: 「Copilot CLIが不正なJSON（途中で切れたJSON）を返した場合、パースエラーはどのように処理されますか？」
**期待**: parseLine try-catchで安全に処理されること

### QE-368 [H: セッション継続性 / N: エージェント管理]
**プロンプト**: 「セッション名が255文字を超える場合、Copilot CLIは正常に動作しますか？」
**期待**: セッション名の長さ制限があること

### QE-369 [J: ディレクトリ構造 / C: ファイル生成・検出]
**プロンプト**: 「workspace/.github/copilot-instructions.mdが手動で削除された状態でCLIを実行した場合、エラーになりますか？」
**期待**: ensureWorkspaceRepoが再生成すること

### QE-370 [G: RAGコンテキスト / K: 並行安全性]
**プロンプト**: 「RAGインデックスへの書き込みとRAG検索が同時に実行された場合、データ整合性は保たれますか？」
**期待**: SQLiteのトランザクション分離で安全であること

### QE-371 [M: API整合性 / L: セキュリティ]
**プロンプト**: 「DELETE /api/projects/:id エンドポイントは、実行中のrunがある場合でもプロジェクトを削除しますか？」
**期待**: 実行中のrunを先に停止するか、削除を拒否すること

### QE-372 [B: スキル連携 / J: ディレクトリ構造]
**プロンプト**: 「スキルファイルのパスに空白文字を含む場合、syncSkillFilesは正常に動作しますか？」
**期待**: パス処理が空白を正しくハンドルすること

### QE-373 [F: E2E自動化 / A: 応答品質]
**プロンプト**: 「CLI実行中にプロセスがSIGTERMを受信した場合、子プロセスは正常に終了しますか？」
**期待**: graceful shutdown でCLI子プロセスもkillされること

### QE-374 [D: MCP活用 / M: API整合性]
**プロンプト**: 「MCPプリセットとユーザー設定が同じサーバー名を持つ場合、どちらが優先されますか？」
**期待**: ユーザー設定が優先され、プリセットを上書きすること

### QE-375 [L: 入力バリデーション / セキュリティ]
**プロンプト**: 「メッセージ内容がnullまたはundefinedの場合、RAGトークン抽出はクラッシュしますか？」
**期待**: null/undefinedチェックがあること

### QE-376 [G: RAGコンテキスト / I: ファイル更新]
**プロンプト**: 「rag-context.mdへの書き込み中にディスクフルエラーが発生した場合、CLIの実行は続行されますか？」
**期待**: writeFileSync失敗をtry-catchし、CLI実行は続行すること

### QE-377 [K: 並行安全性 / N: エージェント管理]
**プロンプト**: 「credential proxyが起動に失敗した場合（ポート競合など）、CLI実行はどうなりますか？」
**期待**: proxy起動失敗をキャッチし、エラーをユーザーに返すこと

### QE-378 [C: ファイル生成・検出 / L: セキュリティ]
**プロンプト**: 「アーカイブダウンロードで、zip内のファイル名に../を含む場合（Zip Slip）、パス走査攻撃は防止されますか？」
**期待**: archiver libraryがファイル名を正規化するか、検証すること

### QE-379 [H: セッション継続性 / E: デバッグ]
**プロンプト**: 「DBファイルが破損した場合（不正なSQLiteファイル）、アプリケーションは起動時にクラッシュしますか？」
**期待**: DB初期化エラーをキャッチし、再作成するか明確なエラーを返すこと

### QE-380 [M: API整合性 / A: 応答品質]
**プロンプト**: 「GET /api/projects でプロジェクトが100件以上ある場合、レスポンスにページネーションはありますか？」
**期待**: ページネーションまたは上限が設定されていること
